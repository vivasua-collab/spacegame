# Task 27 — Авто-переработка базовых ресурсов, газовый склад, принуждение резервов, синергия генераторов

Дата: 2026-08-31 · Владелец: жалоба по реальному сейву `Galaxy #213397` (tick 204, Phi Phoenicis I, toxic-атмосфера)

## Диагноз (по дампу сейва + коду)

| # | Жалоба владельца | Причина (код/данные) |
|---|---|---|
| 1 | Синергия 3 солнечных станций не отображается/не работает | Правила синергии не содержат правила «генератор+генератор»: `power_boost` (generator←consumer) требует смежных ПОТРЕБИТЕЛЕЙ, а соседние солнечные станции — генераторы → бонус 0, панель «Синергия» пуста |
| 2 | 3 переработчика не производят Si/Fe, руды копятся | Переработка существует ТОЛЬКО через ручную очередь (`processProductionQueue`); в сейве `productionQueues = 0` — авто-переработки нет вообще |
| 3 | Переработчик должен производить только базовые строительные ресурсы | Базовые строительные ресурсы по каталогу costs: **Fe, Si, Al, C, Cu, Ti**; авто-режим отсутствует, специализация не ограничена базовыми |
| 4 | Нет доступа к пулу ресурсов | Пул = `planet.resources`, доступ есть только у очереди; переработчики без очереди пул не трогают |
| 5 | Склады: рудный/элементарный/строительный + нужен газовый | v3.0: ore/processed/highTech; газы (`atmospheric`) уходят в РУДНЫЙ склад (`getWarehouseType`) |
| 6 | Минимальные пороги хранения не работают | `reserves[].minimum` НИГДЕ не принуждаются — `canStoreResource` игнорирует резервы |
| 7 | Газовый экстрактор заморозил всё | toxic-атмосфера: 5 газов × 1.38/тик; несконвертированные (CO2/NH3/H2S/SO2 — нет DIRECT_GAS_MAP) вечно копятся в рудном складе (5000) → `canStoreResource=0` → добыча и конвертация H2 встают |

## Решение

### R-27-a Синергия (data-driven, synergy.json)
1. **generator_cluster**: generator ← generator, sameSubtypeOnly, `energy_generation`, +5%, decay 0.5 — кластер солнечных станций получает мизерный, но реальный бонус; отображается в диалоге автоматически.
2. **mine_processor** (возврат NEXT-2): processor ← extractor, `processing_speed`, +15%, decay 0.5.
3. **warehouse_production** (возврат NEXT-2): processor ← storage, `processing_speed`, +20%, decay 0.5.
   → `processing_speed` уже интегрирован в `processProductionQueue` и будет применён в новом авто-режиме.

### R-27-b Авто-переработка базовых строительных ресурсов (engine)
- Новый шаг тика `processAutoProcessing(planet)` (после добычи, до очереди).
- Экземпляры `processor` (все слои): universal — все базовые рецепты; specialized в `metal_smelting`/`nonmetal_smelting` — только рецепты своей категории с бустом; прочие специализации НЕ авто (продвинутые ресурсы — refinery/synthesizer, решение владельца).
- Базовые рецепты: `smelt_fe, smelt_si, smelt_al, smelt_c, smelt_cu, smelt_ti` (новый data-модуль `src/data/auto-processing.ts`).
- Пропускная способность: (10 ед. входа / recipe.time) × (1 + (L−1)·0.15) × synergy(processing_speed) — за рецепт на экземпляр.
- Входы НЕ расходуются ниже резерва `minimum` руды (пол); выходы — через `canStoreResource` (ёмкость + долг резервов); yield/чистота — существующие `calculateProcessorOutputMultiplier` (universal ×0.75, specialized буст).
- Гейт энергии: `planet.energyBalance ≤ 0` → авто-режим стоит (потребление переработчиков уже в балансе).
- Ручная очередь не тронута.

### R-27-c Газовый склад (v3.1)
- `WarehouseCapacities.gas?: number`; `GAS_WAREHOUSE_BASE = 2000`; `getWarehouseType`: `atmospheric → 'gas'` (лёд остаётся в рудном); `calculateWarehouseCapacities`/`createDefaultWarehouse` считают gas (расширение зданиями — в будущем).
- Совместимость: старые сейвы без `capacities.gas` → фолбэк базы; после первого тика recalc заполняет.

### R-27-d Принуждение резервов (только стартовая база)
- `canStoreResource`: `available = capacity − used − reserveDebt`, где debt = Σ по резервам ДРУГИХ ресурсов того же склада `max(0, minimum − stock)`.
- Один тип руды не может занять место минимумов других (жалоба №6); долг мал и относится к базовой части — новые склады расширяют вместимость, пороги не меняются, новым объёмом можно забить одним типом.

- Панель «Склад» (planet-view): 4 полосы — Рудный / Элементы / Высокотех / Газовый (used/cap).
- Описание processor: авто-режим базовых руд.

## Результат

Все 7 пунктов жалобы выполнены (гейты: lint 0/48, tsc 156, 555/555, validate 4/4):
1. **Синергия солнечного кластера**: generator_cluster (+5%/соседа, decay 0.5) — отображается в диалоге (браузер: «2 смежн. → +7.5% (генерация энергии)», выработка 28.6/тик с ×1.075).
2. **Авто-переработка**: processAutoProcessing — переработчики работают БЕЗ очереди (браузер: элементы 896 → 2339 за ~600 тиков, 3 процессора).
3. **Только базовые ресурсы**: Fe/Si/Al/C/Cu/Ti (объединение costPerLevel); metal/nonmetal_smelting — буст в рамках базовых; прочие специализации — refinery/synthesizer (ручная очередь).
4. **Пул ресурсов**: planet.resources — прямой доступ авто-режима (входы/выходы с полами и ёмкостями).
5. **Газовый склад v3.1**: отдельный склад 2000 ед. (база), атмосферные газы — в него; лёд — в рудном; UI — 4 полосы; совместимость старых сейвов (фолбэк).
6. **Резервы принуждаются**: долг минимумов в canStoreResource — один тип руды не забивает склад (браузер: Fe-ore остановился ровно на 60/60, Si-ore 50/50).
7. **Газовый экстрактор не «замораживает»**: газы идут в газовый склад (регрессионный тест: 100 тиков toxic — рудный склад не тронут).

Дополнительно: R-27-sec — подтверждение удаления сейва (AlertDialog) после инцидента потери сейвов (восстановлены из дампа R-26).
