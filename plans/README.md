# Протокол планирования работы (PLANS)

> **Правило введено владельцем 2026-08-31:**
> «Кроме worklog создавай план работы и отмечай выполненные пункты для каждой задачи».

## Правила

1. **Перед началом задачи** агент создаёт файл плана:
   `plans/YYYY-MM-DD-<task-id>-<slug>.md`

2. **Структура плана** (обязательная):
   - Заголовок: Task ID, дата, источник запроса (цитата/пересказ от владельца)
   - Секция «Цели» — что должно быть сделано (декомпозиция на пункты)
   - Чеклист с чекбоксами `- [ ]` / `- [x]` — **обновляется по ходу работы**
   - Секция «Открытые вопросы» — вопросы к владельцу + принятые решения
   - Секция «Результат» — заполняется в конце (статус: done / partial / blocked)

3. **Отметка пунктов**: пункт отмечается `[x]` ТОЛЬКО когда он реально завершён
   (код написан, тесты зелёные, lint чист). Пункты, отменённые по ходу,
   помечаются `[~]` с пояснением.

4. **План ≠ worklog**: план отвечает «что и в каком статусе», worklog — «что
   делалось по шагам». Оба файла обязательны. План коммитится вместе с кодом.

5. **Восстановление после сбоя**: первым делом новой сессии — прочитать
   `worklog.md` (хвост) + последний план в `plans/`, сверить с `git log`,
   до-завершить незакрытые пункты (см. пример: задача R-22 восстановлена
   по коммиту `4c78031` после падения сессии).

## Шаблон

```markdown
# План: <Task ID> — <название>
Дата: YYYY-MM-DD · Источник: <цитата владельца / ссылка>

## Цели
<краткое описание>

## Чеклист
- [ ] пункт 1 (реализация)
- [ ] пункт 2 (тесты)
- [ ] пункт 3 (гейты: lint/tsc/test/validate)
- [ ] пункт 4 (docs)
- [ ] пункт 5 (commit + push)
- [ ] пункт 6 (worklog + чекпоинт)

## Открытые вопросы
- ... → Решение: ...

## Результат
- Статус: done | partial | blocked
- ...
```
