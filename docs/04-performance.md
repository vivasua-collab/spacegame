## 1. Симуляция (тиковая система)

### 1.1 Слоистая симуляция

Производительность при 1000+ систем достигается за счёт **слоистой симуляции** — разные зоны обрабатываются с разной детализацией:

| Зона | Радиус | Частота тиков | Модель |
|------|--------|---------------|--------|
| **Активная** | 3 системы вокруг игрока | Каждые 100мс при x1 | Полная симуляция (добыча, крафт, движение) |
| **Видимая** | 10 систем | Каждые 1с | Упрощённая (прирост ресурсов по формуле) |
| **Дальняя** | Остальные | Раз в 10с | Модель прироста по формуле |

### 1.2 Web Worker

- Симуляция в отдельном потоке (`Web Worker`)
- Связь с UI через `postMessage`
- UI не блокируется при тяжёлых расчётах
- Игровой цикл независим от частоты рендеринга

### 1.3 Упрощённая модель для мелких фракций

Мелкие фракции и независимые колонии (см. [71-minor-factions.md](./71-minor-factions.md)) используют **упрощённую модель**:
- Экономический прирост по формуле (без посимвольной добычи)
- Обновление раз в N тиков (не каждый тик)
- Минимальный флот (только оборона)
- Это позволяет иметь сотни мелких фракций без падения производительности

### 1.4 Тиковая система

- 1 тик = 1 игровой день
- Скорости: пауза (0), x1, x5, x15, x50
- При ускорении: `Math.min(speed, 50)` итераций экономики за тик
- Активная пауза: отдача приказов во время паузы

## 2. Рендеринг карты галактики

### 2.1 PixiJS с WebGL

- WebGL-рендерер (с fallback на Canvas)
- Аппаратное ускорение для тысяч спрайтов
- OffscreenCanvas для тяжёлых вычислений

### 2.2 LOD (Level of Detail)

| Зум | Отображение |
|-----|-------------|
| < 1x | Кластеризованные точки (системы группируются) |
| 1x–10x | Точки систем с цветами звёзд |
| 10x–40x | Иконки систем с названиями |
| 40x–80x | Полноценные иконки + планеты + JP |

### 2.3 Спрайт-пулинг

- Переиспользование спрайтов для тысяч звёзд
- Избегание garbage collection при рендеринге
- Batch-рендеринг для одинаковых спрайтов

### 2.4 Миникарта

- Отдельный canvas при зуме > 3x
- Показывает положение камеры в галактике
- Клик по миникарте → перемещение камеры

## 3. Память

### 3.1 Ленивая загрузка систем

- Не держать все 1000 систем в памяти одновременно
- Загружать системы по мере приближения камеры
- Выгружать далёкие системы (с сохранением состояния в SQLite)

### 3.2 Частичные обновления

- Только изменённые сущности ре-рендерятся
- Zustand selectors для минимизации ре-рендеров
- Иммутабельные обновления (Immer) — React.memo работает корректно

### 3.3 Сжатие сохранений

- `systemMap` исключается из JSON (восстанавливается из `systems`)
- `bakedModel` исключается из JSON (восстанавливается из seed)
- Размер сохранения уменьшен вдвое
- Обратная совместимость со старым форматом

### 3.4 BakedGalaxyModel

-Immutable снимок химии галактики после генерации
- Lookup-структуры (`oreMap`, `elementMap`, `atmosphericMap`) для O(1) доступа
- Не пересчитывается при каждом тике — генерируется один раз при `newGame`/`loadGame`

## 4. Профилирование и метрики

### 4.1 Метрики производительности

| Метрика | Цель | Измерение |
|---------|------|-----------|
| FPS при рендеринге галактики | 60 FPS | PixiJS stats |
| Время тика экономики (x1) | < 16мс | Performance.now() |
| Время сохранения | < 1с | AbortController + таймаут 30с |
| Потребление памяти | < 500 МБ | Performance.memory |
| Время загрузки сохранения | < 2с | Performance.now() |

### 4.2 Узкие места (известные)

- 500 систем в галактике — может тормозить при рендеринге (требует LOD)
- `chemistry-generator.ts` (1704 строки) — генерация при newGame может занимать 1-2с
- Прямые мутации в `game-store.ts` — вызывают лишние ре-рендеры (см. P2 в [STATUS.md](./STATUS.md))

### 4.3 Планируемые оптимизации

- Web Worker для симуляции (Etap 2.5+)
- LOD для карты галактики (Etap 4)
- Ленивая загрузка систем (Etap 4)
- Кластеризация звёзд при далёком зуме (Etap 4)

## Принципы оптимизации

1. **Сначала правильно, потом быстро** — предпочтение читаемому коду, оптимизация по мере необходимости
2. **Измерять перед оптимизацией** — профилирование перед рефакторингом
3. **Слоистая симуляция** — основная стратегия для 1000+ систем
4. **Упрощённая модель для мелких фракций** — сотни мелких акторов без падения производительности
5. **Иммутабельность** — React.memo и Zustand selectors работают корректно только с иммутабельными обновлениями
