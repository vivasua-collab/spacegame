## 1. Вариант A: «Веб-нативный» (Рекомендуемый)

> **Обоснование**: Мы уже работаем в среде Next.js. Максимальная скорость разработки, мгновенная доступность через браузер, простота итераций.

| Компонент | Технология | Обоснование |
|-----------|------------|-------------|
| **Фреймворк** | Next.js 16 + TypeScript | Уже настроен, App Router, SSR/CSR гибкость |
| **Рендеринг игры** | HTML5 Canvas + PixiJS 8 | Быстрый 2D-рендеринг галактики, WebGL с fallback на Canvas |
| **UI-оболочка** | React + shadcn/ui | Панели, формы, кнопки — уже есть в проекте |
| **Симуляция (ядро)** | TypeScript классы в отдельном модуле | Чистая логика без UI-зависимостей, запускается в Web Worker |
| **Состояние игры** | Zustand + Immer | Быстрое иммутабельное обновление больших деревьев данных |
| **База данных** | SQLite (через Prisma) | Сохранения, справочники элементов/рецептов, параметры планет |
| **Хранение ресурсов** | TypeScript-модули (не JSON) | Статические таблицы (элементы, рецепты, модули, тех-дерево) |
| **Анимации** | Framer Motion | UI-переходы, анимации панелей |

**Плюсы**:
- Максимальная скорость разработки (всё в одном проекте)
- Доступность через браузер — не нужно ничего устанавливать
- TypeScript — типобезопасность на всём стеке
- PixiJS — проверенный движок для 2D-игр с WebGL
- Простой деплой — один сервер

**Минусы**:
- Производительность ниже чем у нативных движков
- Сложнее реализовать 3D (если понадобится)
- Web Worker имеет ограничения по передаче данных

**Оценка**: ⭐⭐⭐⭐⭐ — лучший выбор для прототипа и MVP

## 2. Вариант B: «Веб + Desktop» (Electron)

| Компонент | Технология |
|-----------|------------|
| **Оболочка** | Electron + Next.js |
| **Рендеринг** | PixiJS 8 (Canvas/WebGL) |
| **Симуляция** | TypeScript (основной поток + Worker Threads) |
| **Хранение** | SQLite + файловая система |
| **Всё остальное** | Как в Варианте A |

**Плюсы**:
- Нативный доступ к файловой системе (быстрые сохранения)
- Worker Threads вместо Web Workers (быстрее обмен данными)
- Можно играть оффлайн
- Лучше производительность симуляции

**Минусы**:
- Нужна установка приложения
- Двойная упаковка (Electron ≈ 150 МБ)
- Сложнее обновлять
- Те же ограничения по 3D

**Оценка**: ⭐⭐⭐⭐ — хороший вариант для релизной версии

## 3. Вариант C: «Игровой движок» (Godot 4)

| Компонент | Технология |
|-----------|------------|
| **Движок** | Godot 4 (C# / GDScript) |
| **Рендеринг** | Встроенный (2D + 3D) |
| **Симуляция** | C# скрипты |
| **Хранение** | SQLite + JSON + бинарные сохранения |
| **UI** | Встроенные Control-узлы Godot |

**Плюсы**:
- Нативная производительность
- Встроенный 2D/3D рендеринг
- Экспорт на Desktop + Mobile + Web
- Бесплатный и open-source
- Встроенная система сцен и узлов
- C# для сложной логики (симуляция, AI)

**Минусы**:
- Совершенно другой стек (не Next.js/React)
- Кривая обучения Godot
- Нельзя использовать shadcn/ui, React и т.д.
- Нет горячей перезагрузки как в вебе
- Дольше цикл разработки для веб-разработчика

**Оценка**: ⭐⭐⭐ — мощный, но требует переключения стека

## 4. Вариант D: «Гибридный» (Next.js + Godot WASM)

| Компонент | Технология |
|-----------|------------|
| **UI / Меню** | Next.js (React + shadcn/ui) |
| **Карта галактики / Бой** | Godot 4 → HTML5 экспорт (iframe) |
| **Симуляция** | SharedWorker (TypeScript) |
| **Связь UI ↔ Игра** | postMessage API |

**Плюсы**:
- Лучшее из двух миров: красивый UI на React + мощный рендеринг на Godot
- Можно постепенно переписывать UI на Godot

**Минусы**:
- Максимальная сложность архитектуры
- Задержки при обмене сообщениями
- Два стека для поддержки
- Godot HTML5 экспорт медленнее нативного

**Оценка**: ⭐⭐ — слишком сложно для MVP

---

## 5. Рекомендация

**Для данного проекта принят Вариант A (Веб-нативный)**:
1. Мы уже в среде Next.js — нет переключения контекста
2. PixiJS отлично справляется с 2D-рендерингом карт на десятки тысяч объектов
3. Web Worker обеспечивает независимость симуляции от рендеринга
4. SQLite через Prisma — быстрые сохранения и справочники
5. Быстрый цикл итераций — правим код, обновляем страницу

В будущем можно мигрировать на Вариант B (Electron) для лучшей производительности и оффлайн-доступа.
