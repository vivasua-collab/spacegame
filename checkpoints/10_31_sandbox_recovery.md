## Уроки (для будущих восстановлений)

- **`bun run dev` НЕ годится для фонового запуска**: скрипт содержит pipe
  `next dev | tee dev.log` — `tee` умирает вместе с shell-сессией и утягивает
  всю цепочку. Только прямой `node node_modules/.bin/next dev` с
  перенаправлением `>` и double-fork `( ... & ) &`. INSTRUCTIONS.md это
  документировал — следовать ему буквально.
- **Не зондировать инфраструктурные порты песочницы сырыми соединениями**
  (`/dev/tcp` на 19005) — harness разрывает tool-сессию (403 broken session) с
  потерей всех последующих tool-вызовов до нового хода.
- После сброса песочницы порядок восстановления (по INSTRUCTIONS.md):
  `bun install` → проверить `.env` (абсолютный путь БД) → `bun run
  db:generate` → остановить заглушку песочницы на :3000 → double-fork запуск.
