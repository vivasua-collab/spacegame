## 1. Проблема (аудит R-38 §2)

В R-37 миграция рассчитана на тела с ЕЩЁ НЕ материализованными залежами
(dm=0 — версионная материализация при колонизации). Если сейв содержит тело,
уже колонизированное старым кодом (dm=1, физические залежи записаны, dv
старая/отсутствует, свод посчитан устаревшей семантикой агрегации — R-36
перезаписывал выбранный уникальный ресурс константами 4–6 без согласования
с физикой), replay невозможен (залежи уже физические) — устаревший свод
оставался навсегда: UI обещал добычу, которой нет в гексах.

## 2. Выбранная стратегия миграции (явная, документированная)

**«Физика сохраняется, свод пересчитывается»** — `migrateMaterializedBodySummary`
(generate-resources.ts), вызывается из `deserializeGameState` для каждого тела
с `dm=1 && hexes>0` и устаревшим контрактом свода:

| Требование аудита R-38 §2.3 | Реализация |
|---|---|
| Не терять добытые ресурсы | склад `resources` не читается-не пишется миграцией (тесты A3/B9 сверяют бит-в-бит) |
| Не восстанавливать истощённую залежь | гексы/deposits не трогаются; qty=0 кортежи остаются 0; истощённые (не пишутся кодеком) не воскрешаются (A4/A5) |
| Не сбрасывать прогресс/колонизацию/здания/склад | миграция пишет ТОЛЬКО `resourceDeposits` + `depositSummaryVersion` (A3: buildings/owner/склад идентичны) |
| Не генерировать залежи поверх существующих | никакого replay/assign для dm=1 — только агрегация фактических залежей |
| Не оставлять устаревшую сводку | свод = Σ(залежи × доля выхода) + гарантия hexCount=0 (контракт R-37 «свод = физика»), устаревшие значения удаляются (A3/B2) |
| Детерминизм и совместимость формата | оценки гарантии — именованный дочерний поток `derive` от ds (соль: версия свода + id тела); формат v3 расширен опциональным полем `sv`; C1/C4 |
| Не считать старую залежь эквивалентной новой (§2.4) | **dv НЕ поднимается** — версия физики остаётся честной; C5: dv=2 сохраняется в памяти и в сейве, sv=1 — свидетельство миграции СВОДА |
| Молчаливая регенерация запрещена (§2.5) | её нет: тело, материализованное старым кодом, НЕ получает залежи новой генерации (следовые ultra/усиленная уникальная залежь отсутствуют — задокументированное ограничение, см. §9.1) |
| Идемпотентность повторной загрузки (§2.6) | поле `sv` (DEPOSIT_SUMMARY_VERSION=1): после первой миграции повторные загрузки не пересчитывают свод (A6: load→save→load побайтно стабилен; браузер: повторная Load — без миграции) |
| Ленивая генерация сохранена (§2.7) | dm=0 тела не затрагиваются: залежей в гексах нет, ds на месте, sv не инъецируется (A8); размер сейва не растёт |

**Отказ миграции** (A7): повреждённые числа (NaN в агрегате) → тело сохраняет
прежний свод, атомарность на тело, загрузка продолжается, lookups загруженной
галактики валидны; отказ учитывается в журнале (`отказов N`).

**Сопутствующие исправления целостности версий:**
- `materializePlanetDeposits` (replay при колонизации) теперь честно ставит
  `depositRngVersion = DEPOSIT_RNG_VERSION` — физика ВОСПРОИЗВЕДЕНА текущим
  кодом (раньше dv оставался старым и после replay, ложно помечая свежие
  залежи как «до R-36/37»; C3/C5: после колонизации dv=3);
- генерация помечает `sv=1` у тел с гексами (пул при генерации считается
  текущим контрактом; B10).

## 6. Браузерная верификация (живой UI, публичный путь)

Сценарий: старый сейв (seed 424242, 60 систем, 2 колонии с геймплеем: частично
истощённая залежь, склад Fe-ore 432.5, постройки; состарен — без dv/sv, своды
dm=1 тел испорчены ×3) → POST /api/save → браузер.

1. **Загрузка старого сейва:** консоль — `[save] R-38: миграция свод-пулов
   материализованных тел (свод = физика): пересчитано 2, отказов 0 — физика/
   склад/прогресс добычи сохранены, dv тел не изменён` + перепись R-37
   (235 ожидающих). Вкладка «Ресурсы»: **Fe • 87 гексов • 158.6K** —
   мигрированный свод (устаревший обещал бы ~480K). 0 ошибок страницы.
2. **Буровая (порог глубины на старом сейве):** гекс 25 (Y-ore qty 17,
   minSourceLevel 2): буровая **L1** добывает Ba-ore (порог 1) и трансурановые
   Np/Am (fallback «обычная порода»), **Y-ore НЕ добывает** — негативный тест.
   Апгрейд **L2** → «⛏Иттриевая руда 16» на складе — позитивный тест.
3. **Истощение:** панель гекса — «Иттриевая руда **0**» (залежь 17 → 0;
   склад 16.99…=полная, UI округляет вниз); 500+ тиков после истощения —
   объём не растёт (B4 в живом UI).
4. **Сохранение:** Save → PUT (tick 12250). Инспекция сейва через API:
   **sv=1, dm=1, dv=undefined** (не инъецирован), залежь Y-ore в сейве
   ОТСУТСТВУЕТ (истощённые не пишутся), буровая L2, склад Y-ore 16.99…,
   Fe-ore 2173.
5. **Перезагрузка:** reload → Load → буровая L2 на месте, склад идентичен
   (Y-ore 16, Fe-ore 2173, рудный 4784/5000).
6. **Повторная загрузка:** reload → Load того же сейва → состояние идентично;
   **миграция НЕ срабатывает** (sv=1; консоль: всего 2 сообщения R-38 за 4
   загрузки — оба от старых сейвов).
7. БД после: **0 сейвов** (тестовый удалён через DELETE /api/save).

**Колонизация через UI в загруженном сейве:** фаза `playing` не даёт кнопки
«Колонизировать» (колонизация — начальная фаза новой игры; дополнительные
колонии — флот-приказы, UI вне MVP). Колонизация старых сейвов покрыта
движковыми тестами (A3/A6/C3 колонизируют через публичный `colonizePlanet`);
в загруженном сейве 2 колонии работают (добыча подтверждена п.2–3). Это
ограничение ДИЗАЙНА игры (не регрессия R-38), зафиксировано честно.

## 9. Ограничения и остаточные риски (явно)

1. **Старая физика остаётся старой (осознанно):** тело, материализованное
   до R-36/R-37, НЕ получает следовые ultra-залежи и усиленную уникальную
   залежь новой генерации — на нём выбранный уникальный ресурс может
   отсутствовать физически (свод честно это отражает). Регенерация без
   потери прогресса невозможна (запрещена заданием §2.5). Планетарная
   выборка свежих тел не затронута (тесты 18/21/25 deposits.test).
2. **Оценки гарантии мигрированных тел отличаются от генерационных:** фаза
   гарантии (hexCount=0) при миграции берётся из именованного дочернего
   потока derive(ds, id), а не из продолжения deposit-потока — значения
   детерминированы и воспроизводимы (C1/C4), но численно отличаются от того,
   что дала бы генерация. Отображаются как «геол. оценка» — контракт hexCount=0.
3. **Транзит R-37→R-38:** сейвы, созданные кодом R-37 с колонизированными
   телами (dv оставался старым после replay), при загрузке под R-38
   перемигрируются один раз (свод пересчитается тем же контрактом — оценки
   гарантии могут смениться численно; физика/склад не меняются). В БД 0 сейвов
   — влияние нулевое.
4. **UI склада показывает округление:** дробные количества руд на складе
   отображаются округлённо вниз (Y-ore 16.99 → «16») — до R-38 (pre-existing),
