## 2. Замечание P1 (PRNG) — вердикт: **PASS**

### 2.1 Диагноз (подтверждено замечание аудитора)

Прежний `src/core/prng.ts` назывался `Xoshiro256`, но хранил 4×uint32 и
выполнял 32-битные операции с КОНСТАНТАМИ xoshiro256**:
`t = s[1] << 17`, `s[3] = rotl(s[3], 45)` (45 ≡ 13 по модулю 32 в JS).
Получался неэталонный «мешап»: скрамблер и порядок XOR совпадали с
xoshiro128**, но линейное преобразование — нет. Ни одному каноническому
алгоритму код не соответствовал; тесты среднего/std этого доказать не могли.

Эталон: официальный **xoshiro128\*\* 1.1** (Blackman & Vigna,
http://prng.di.unimi.it/xoshiro128starstar.c — файл получен 2026-10-26) —
`t = s[1] << 9`, `s[3] = rotl(s[3], 11)`. Примечание в первоисточнике:
«version 1.0 had mistakenly s[0] instead of s[1] as state word passed to the
scrambler» — скрамблер по s[1] в нашем коде уже соответствовал версии 1.1.

### 2.2 Решение

Выбран вариант аудитора «корректный 32-битный алгоритм» — канонический
**xoshiro128\*\* 1.1**: в JS нет нативного uint64 (BigInt в горячем пути —
избыточная цена), 128 бит состояния достаточно при принятой схеме
derive()-подгенераторов (каждый поток — независимое состояние; jump-ahead
избыточен). 64-битный xoshiro256** потребовал бы BigInt-перехода на каждый
nextU32() и/или смены макета снимка состояния в сейвах.

Изменения `prng.ts`:
- переход состояния: `t = s1 << 9`, `finalS3 = rotl(ns3, 11)` (константы 1.1);
- класс переименован `Xoshiro256` → **`Xoshiro128StarStar`** (21 файл:
  10 src + 10 tests + 1 script; единственное упоминание «Xoshiro256» осталось
  в историческом комментарии миграции);
- API, сидирование и макет снимка НЕ менялись (см. совместимость).

### 2.3 Эталонные тесты (прежде отсутствовали — теперь есть)

`tests/prng-reference.test.ts` (5 тестов): векторы сгенерированы ОФИЦИАЛЬНЫМ
C-кодом (xoshiro128starstar.c + splitmix64.c, gcc -O2 -Wall -Wextra, 0
предупреждений; харнесс с сидированием по конвенции проекта):
- SEED-векторы: 10 seed (0, 1, 7, 42, 12345, 999999, 2^31−1, 2^32−1, 2^53−1,
  −7) → 4 слова состояния + первые 8 выходов — бит-в-бит;
- STATE-векторы: 5 прямых состояний (путь fromState, мимо splitMix64);
- SM64-векторы: полные uint64-выходы splitMix64 → низкие 32 бита = словам;

- регрессионная привязка миграции (первый выход seed 42 = 0x0c2ec5ae —

−0), arms 0/NaN/−3/2.7, NaN в spread/armWidth/armTwist, и NaN ≡ radius 0
