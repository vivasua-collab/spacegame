# Чекпоинт — Save-System Audit Fix (Issue #25, follow-up) — 2026-10-29

**Ветка:** main. **База:** fa50198 (ORE-POOLS-RUNTIME-01, Task 71).
**Задача:** два дефекта системы сейвов, обнаруженных владельцем после
миграции формата v4: (1) метаданные БД сообщают неправильную версию
формата; (2) сообщение об ошибке загрузки не соответствует v4.

## Диагноз

### Д1 — метаданные БД
- `POST /api/save` (route.ts:164) и `PUT /api/save/[id]` (route.ts:153)
  хардкодили `version: 1` («current serialization format version»,
  «unchanged on PUT»). При этом клиент с ORE-POOLS-RUNTIME-01 пишет state
  в формате **v4** (`compactSaveV4` → маркер `fmt: 4` в JSON).
- Следствие: каждая новая/обновлённая запись сообщала в `GameSave.version`
  ложную «1»; PUT-комментарий «unchanged on PUT» был неверен вдвойне —
  PUT заменяет state целиком, метаданные обязаны описывать НОВЫЙ state.
- Путь загрузки `version` не читает (отбор по `fmt` внутри state), т.е.
  дефект — наблюдаемость/честность метаданных, не порча загрузки.

### Д2 — сообщение об ошибке загрузки
- Тост отказа загрузки (page.tsx:160): «Сейв повреждён или записан в
  старом формате (**v1/v2** не поддерживаются)» — текст эпохи v3 (R-30),
  когда отвергались v1/v2. При `SAVE_FORMAT_VERSION=4` отвергаются
  **v1/v2/v3** (docs/31 §12 — гекс-залежи не мигрируются).
- Сопутствующее: протухшие комментарии «fmt≠3», «формат сейвов v3»,
  «невалидная схема v3» в game-store/factions/game-recovery-contract.

## Исправление

### Д1 — метаданные = фактический fmt
- `src/lib/save-format-v4.ts`: `declaredFormatVersion(parsedState)` —
  честное зеркало маркера `fmt` уже распарсенного state (числовой целый
  ≥1 → как есть; отсутствие/мусор → legacy-дефолт 1, совпадает с
  `default(1)` колонки и домиграционными строками).
- `POST /api/save`: `version = declaredFormatVersion(parsedState)`
  (state уже парсится для валидации «JSON-объект» — нулевая доп. цена).
- `PUT /api/save/[id]`: то же; перезапись legacy-строки (version:1)
  v4-state корректно меняет метаданные на 4.
- API остаётся формат-агностичным хранилищем (отбор чужих версий — на
  загрузке, как задумано docs/31 §12); метаданные теперь не врут ни в
  одну сторону.

### Д2 — текст из единого источника
- `src/lib/save-format-v4.ts`: `REJECTED_LEGACY_FORMAT_VERSIONS` =
  v1..v{SAVE_FORMAT_VERSION−1} (производно — при v5 список обновится сам)
  + `rejectedLegacyVersionsLabel()` → «v1/v2/v3».
- Тост page.tsx строит текст из модуля формата — больше не может
  «протухнуть» при следующей смене версии.
- Комментарии приведены к v4: page.tsx (fmt≠4 + источник текста),
  game-store.ts:639 (fmt≠4, прецедент R-30), game-store.ts:969/1660,
  factions.ts:40-43, game-recovery-contract.ts:19 («формат сейвов v4»).

### Сопутствующий UX-фикс (наблюдение E2E, раскрыт в отчёте)
- Список сейвов кэшировался с монтирования меню (`useEffect [loadSaveList]`):
  сейв, созданный в игре, не появлялся в списке после возврата в меню
  до перезагрузки страницы. Добавлен рефетч при открытии таба Load
  (`useEffect [activeTab, loadSaveList]`).

## Заметки

- Домиграционные строки НЕ перезаписываются (в т.ч. архивная БД не
  трогалась): их `version=1` — исторический факт записи; при перезаписи
  через PUT метаданные обновятся до фактического fmt нового state.
- `SaveInfo` (клиентский тип) поле `version` не раскрывает — UI не
  показывает версию формата (не запрашивалось; API отдаёт её в списке).
