### Решение владельца
Привести во **всех** документах к **реальной физической достоверности**: единая каноническая форма.

### Каноническая форма (источник истины — `30-planets.md` §1.3)
```
Общий закон (ньютоновская гравитация):
    g = G · M / r²

Поверхностная гравитация (через радиус и плотность планеты):
    M = (4/3)·π·r³·ρ
    g_surface = G · (4/3)·π·r³·ρ / r² = (4/3)·π·G·ρ·r

Нормализованная к Земле (используется в генерации):
    g / g_E = (ρ / ρ_E) · (r / r_E)
    где r_E = 6371 км, ρ_E = 5.51 г/см³, g_E = 9.81 м/с²

Проверка (Марс): r = 3390 км, ρ = 3.93 г/см³
    g/g_E = (3.93/5.51) · (3390/6371) = 0.713 · 0.532 = 0.379 g ✓ (факт. 0.378 g)
```

> Ключевой момент: при постоянной плотности степень при `r/r_E` — **первая** (не вторая). Квадратичная зависимость `g ~ r²` физически ошибочна для поверхностной гравитации.

### Правки
- `00-ARCHITECTURE.md` §0.2: расширить запись — добавить ссылку на нормализованную форму и `30-planets.md` §1.3:

  ```
    вычисляется через радиус и плотность: `g/g_E = (ρ/ρ_E)·(r/r_E)` (см. 30-planets.md §1.3).
    Степень при r/r_E — первая (не вторая): вывод через M = (4/3)πr³ρ.
  ```

## Пункт 4: Универсальные vs специализированные переработчики

### Противоречие
`40-buildings.md` v2.0 (стр. 12, 269) постановил: «Специализированные здания переработки (Плавильня, Химический завод, Нефтехимический завод) **заменены на универсальные переработчики**» — то есть специализированные **удалены**, остались только универсальные `processor`/`refinery`/`synthesizer`.

### Решение владельца
Должно быть **2 типа** переработчиков:
1. **Универсальный** — может перерабатывать несколько ресурсов, но с **низким коэффициентом** выхода.
2. **Специализированный** — заточен под переработку конкретного ресурса (или узкой цепочки), с **высоким коэффициентом** выхода.

Логика: специализированный — это **подмножество/апгрейд универсального**. Универсальный здание можно «переделать» (апгрейд с упором в конкретную цепочку) в специализированный. Необходимо предусмотреть механизм специализации и скорректировать документацию. Подготовить план внедрения → [08_27_block_05_processors.md](./08_27_block_05_processors.md).

### Концепция механизма (детализируется в `40-buildings.md`)
- Универсальный `processor` (базовое здание):
  - Принимает **любой** тип входа (металл. руда, неметалл. руда, хим. соединение, лёд).
  - Выход: чистый элемент с **технической чистотой** ~0.70–0.85.
  - Чем больше разных руд активно, тем **медленнее** переработка каждой.
- Специализированный (апгрейд универсального):
  - **Один** тип входа или узкая цепочка (например, `metal_smelting` или `chemical_decomp`).
  - Выход: чистый элемент с чистотой 0.92–0.99 (высшая чистота для электроники/сверхпроводников).
  - **Высокий коэф. выхода** (больше продукта на единицу руды и выше скорость).
  - Получается путём **апгрейда** универсального с упором в конкретную категорию рецептов.
- Взаимодействие с `refinery` и `synthesizer`: `refinery` = специализированный для металлов; `synthesizer` = специализированный для химии/газов. Они существуют как «максимально специализированные» формы. Универсальный `processor` может быть апгрейдом доведён до уровня `refinery`/`synthesizer` по конкретной цепочке, либо сразу строится как специализированный (после исследования).

### Правки в `40-buildings.md`
- §3: переписать раздел, описав **оба типа** с явным указанием «апгрейд с упором в цепочку».
- Указать формулу выхода:
  - Универсальный: `output = oreInput × baseYield × 0.75 × (1 / sqrt(activeRecipes))` (низкий коэф., штраф за мульти-ресурс).
  - Специализированный: `output = oreInput × baseYield × 1.0 × purityBonus` (высокий коэф. без штрафа).
- Добавить таблицу специализаций (какие апгрейды возможны, к какой категории рецептов).
- Описать UI-флоу: выбор «специализировать» на универсальном здании → выбор цепочки → превращение.
