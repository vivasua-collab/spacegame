## Контекст

Запрос владельца: (1) расчёт размера сейва — почему такой большой, какие данные
сохраняются для условно пустой галактики (дерево галактика→звёзды→планеты→гексы→
ресурсы→постройки, склады/наука/корабли дальше; вопрос «всего/осталось — нужно ли
два поля?»); (2) схема оптимизации — возможно, часть полей излишняя; (3) UI —
объединить раздельные вкладки «резерв» и «хранилище», вывод `количество / резерв`,
ниже резерва красный / выше зелёный. Сейвы владельцем удалены → анализ на эталонной
генерации (seed 42, 200 систем, конфиг newGame). План:
`plans/2026-08-31-task28-save-format-v2.md` (Task ID 28).

## Выполненные задачи

- **Анализ** (`scripts/save-size-analysis.ts`, npm `save:size`): 200 систем /
  531 планета / 418 лун / 35 369 гексов / 276 427 залежей = **31.42 МБ** (v1).
  Профили по сущностям/полям (байты значений + имена ключей): залежи 21.9 МБ
  (70%) — из них ~11 МБ имена ключей × 276k и ~8.6 МБ хвосты availability
  (ср. 18.4 симв.); свод resourceDeposits 6.4 МБ; coord/пустые поля застройки
  ~2.0 МБ; пустые слоты 0.18 МБ (не цель); orbitalPeriod/gravity/systemId < 0.02 МБ
  (не трогаем). Ответы: в залежи ОДНО поле (остаток) — дублей «всего/осталось»
  нет; постройки уже внутри гексов — отдельная секция создала бы дубль.
- **Формат v2** (`src/lib/save-format-v2.ts`, маркер `fmt: 2`): залежи →
  кортежи `[el, avail(3 зн.), qty, depth]`; свод → кортежи
  `[el, total, avg, tierIdx, hexCount, max]` (RNG-контент агрегата сохранён —
  дроп невозможен); гексы без coord (`generateHexCoords` экспортирован из
  hex-grid.ts, порядок массива = сетка), без buildingId/Level у пустых, без
  deposits:[]; звёзды — 4 значащих цифры. Слоты не тронуты (0.6%). Encode —
  чистая функция; decode — до zod-валидации; v1-сейвы без fmt читаются как
  раньше; идемпотентность сохранена. `serializeGameState`/`deserializeGameState`
  (game-store) подключены, БД хранит v2.
- **Результат:** 31.42 → **8.86 МБ (−71.8%)**, gzip 5.26 → 2.28 МБ.
- **UI** (`planet-view.tsx` WarehousePanel): «Резервы» + «Хранимые ресурсы» →
  ОДИН список «Хранилище · количество / резерв»: союз ресурсов (кол-во > 0) и
  резервов (в т.ч. 0/мин — красные); резервные первыми по приоритету; ниже
  резерва — красный, на/выше — зелёный, без резерва — нейтральный; топливо

  осталась в компоненте для других потребителей).
